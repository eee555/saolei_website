# 计数器表达式差分

`d(expr, n)` 表示当前采样点与前 `n` 个采样点之间的差值，不自动除以步长或时间差。`d(expr)` 等价于 `d(expr, 1)`。步长在当前采样点的上下文求值，必须为正整数，非法步长沿用错误显示。采样模式筛选及同毫秒去重在求值之前完成，步长按最终有序采样点计数，不按事件数或时间长度计数。前驱不足时返回 `NaN`，支持嵌套差分；例如 `d(d(left))` 的前两个点为 `NaN`，`d(d(left, 2), 3)` 的前五个点为 `NaN`。

## 解析方案调查

- 当前使用的 `expr-eval@2.0.2` 支持自定义函数，但调用前先计算参数，回调只能收到参数值，不能访问参数表达式和前一采样上下文。[官方说明](https://github.com/silentmatt/expr-eval#custom-javascript-functions)、[求值源码](https://github.com/silentmatt/expr-eval/blob/v2.0.2/src/evaluate.js)。
- 公共接口没有语法树遍历或惰性函数参数接口。单纯注册有状态的 `d(value)` 无法正确处理条件分支、多个差分调用及嵌套；正则拆分参数也无法可靠处理完整表达式语法。
- 保留原库的解析与求值能力，由 `counterDifference.ts` 集中适配已解析的后缀指令。只将直接的 `d(expr)` / `d(expr, n)` 调用改为库求值器支持的惰性 `IEXPREVAL` 指令，再通过一元 `+` 解引用为数值，确保作为条件或逻辑运算左操作数时不被当成对象；算术、函数、数组、条件分支等仍由原库处理。不新增另一套表达式语法，不使用 `eval` 或 `toJSFunction`。[Expression 源码](https://github.com/silentmatt/expr-eval/blob/v2.0.2/src/expression.js)。

## 内部接口边界

`Expression.tokens`、指令类型和 `IEXPREVAL` 属于依赖内部接口，没有在其 TypeScript 声明中提供。局部类型声明仅在适配模块中描述当前版本的实际结构，不修改依赖声明或其他调用方。升级 `expr-eval` 时必须复查该模块并运行 Analyzer 单元测试；如果上游提供公开的语法树/惰性函数接口，优先替换这一适配。

每个差分参数按采样索引缓存数值，前驱求值与调用顺序无关，未选中的条件分支保持惰性。缓存只存在于一次行采样计算中，不跨录像或配置变更保留。错误沿用计数器的错误显示规则，`NaN` 与正负无穷不作过滤。
