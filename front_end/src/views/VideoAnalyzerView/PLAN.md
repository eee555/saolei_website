## 开发边界

- Analyzer 与原有弹窗播放器独立维护。代码可以互相借鉴，但不引入弹窗播放器的组件、播放状态或应用内播放模块，也不为两者抽取共享播放器实现。仅按已确认需求共享概率配色 `videoPlayerConfig.probabilityColorScheme`；文件解析计数器不再共用 VideoPlayer 的组件、编辑界面或 localStorage 配置，其余配置及图层开关也独立。
- 可以使用相同的外部依赖；Analyzer 的需求和布局独立确定，配置除明确约定的共享项外独立维护，不要求与弹窗保持一致。
- 棋盘部分使用用户维护的 `minesweeper-board` 渲染，不另行实现棋盘渲染器。
- 时间轴绘图使用用户维护的 `@putianyi888/vue3-plots`，复用其图层、坐标转换、自动数值范围及刻度工具；缺少通用绘图能力时先提出完整 feature request，等待用户更新，不在 Analyzer 内另写替代实现。棋盘事件图层按用户要求使用原生 SVG，不要求依赖提供该图层，也不接入视频导出。
- 按键事件合并进轨迹，使用 `MouseTrace` 的内置 Canvas marker，不另建 DOM 图层或图层按钮；接入依赖公开的全部样式 props，额外线型先提出 feature request。
- 后续需求先检查依赖已有能力。更适合由依赖解决的需求，先提出完整 feature request：使用场景、现有缺口、预期行为、输入输出、接口需求、示例和验收标准；等待用户更新后再接入，不添加替代实现绕过依赖。
- 关键帧定位是用户明确批准的例外：在上游时间同步修复前，按“先时间、后索引、前置局面”接入 workaround，不扩展为其他依赖缺口的默认处理方式。
- 分析计算和数据处理按实际需求拆为本目录内的独立 TypeScript 模块，模块职责与接口随需求自然演进，不提前搭建通用分析框架。

## 事件术语

- 录像文件记载的事件统一称为“原生事件”，以 `ms-toollib` 提供的事件数组及索引顺序为准。现有关键帧、鼠标轨迹、按键 marker 及计数器的采样筛选均基于原生事件，不因新增自定义事件改变行为。
- “自定义事件”由用户表达式在原生事件上求值并判定是否发生，不写回录像文件，不插入或改写原生事件数组，也不是计数器的数据轨道。
- 原生事件可以具有相同时间戳；自定义事件采用与计数器“连续采样”一致的毫秒分辨率，每毫秒采样一次，有事件时保留原数组中的最后一个，无事件时沿用此前最近原生事件的全部字段（包括 `time`）再求值和判定。原生事件数组本身不变，关键帧、鼠标轨迹和按键 marker 仍保留原事件顺序及数量。

- 分析页路由为 `/video/:id`，沿用 UserView 的 `/player/:id` 形式，将 `player` 改为 `video`；Hash 地址例如 `#/video/123`。
- `App.vue` 显示 URL 中的录像 ID；原有 `/video` 录像检索页保留。
- 每个页面只对应一份站内录像，不提供页面内录像切换控件，不支持同时打开多份录像；切换录像需要修改 URL 中的录像 ID。
- 根据 ID 加载录像，直接打开或刷新后重新请求该录像。

| 入口 | 链接目标 | 普通点击行为 |
| --- | --- | --- |
| 原有录像预览文字 | 对应录像的分析页 | 打开原有弹窗，保留快速预览行为。 |
| 弹窗标题中的录像 ID | 当前弹窗录像的分析页 | 关闭原弹窗并跳转到分析页。 |

预览入口统一使用 `VideoPreviewLink`，原 `PreviewNumber` 已合并。无有效录像 ID 时显示非交互的 `--`。有 ID 时使用真实链接，支持复制地址、右键菜单及新标签页操作；普通左键点击或 Enter 打开弹窗，Ctrl/Cmd、Shift、Alt 点击和中键操作保留浏览器原生行为，不重复触发整行预览。

### 站内录像加载

- 网站 useSiteReplaySource.ts 只取得原始字节；公共 useReplaySource.ts 独立维护解析和资源生命周期，不依赖站内请求或弹窗播放器模块。
- 先请求 `/video/get_software/?id=<ID>` 获取软件类型，再请求 `/api/video/preview?id=<ID>.<扩展名>` 的原始二进制。
- 使用项目 `$axios` 和 `responseType: 'arraybuffer'`，使用 `ms-toollib` 的 EVF、AVF、MVF、RMV 对应解析类，调用 `parse()`、`analyse()`。
- 页面持有一份可见录像解析对象并提供真实时长。布局切换不重新请求或解析录像；导出从已下载字节另建临时解析对象，不代表用户可以同时打开多份录像，结束时释放该对象。
- URL 中 ID 变化时，取消旧请求、释放旧录像并重置进度为暂停的开头；组件卸载时取消请求并释放录像。
- 旧请求的迟到响应和取消错误不覆盖新请求的状态。解析或分析失败时也释放已创建的 WASM 对象。
- 棋盘区域显示加载状态及 HTTP/解析错误，失败时不伪造数据。
- 已升级至 npm `ms-toollib 1.5.19`，四种录像类及 `BaseVideo` 均已暴露只读 `board` getter。用成功 EVF、失败 EVF、AVF、MVF 和 RMV 验证了矩阵尺寸、完整雷数及邻雷数。原接口需求已解决，不用最终可见局面替代真实底盘。

### 棋盘渲染结构

- `BoardPanel.vue` 使用单个 `MinesweeperBoard` 统一提供棋盘尺寸及可见局面上下文，格子大小支持固定数值、相对比例及自适应，默认自适应，需求与设置见“棋盘通用设置”。
- `background` 插槽仅有一个共享的 `BoardBackground`，不显式传入 `board`，由依赖将当前 `game_board` 转换为背景布尔矩阵。背景跟随已打开局面的开闭状态更新，不受其他图层的开关和不透明度影响；关闭全局和概率图层时仍保留背景、已打开图层及棋盘尺寸。
- 各图层均为前景图层，在 `foreground` 插槽内叠加。从下到上为全局、已打开、概率、鼠标轨迹（含按键 marker）、光标，光标始终位于最上层；按键事件不再单独占据图层。图层透明区域透出下层，光标不拦截鼠标交互。

### 棋盘通用设置

- 棋盘区域右下角设置一列通用设置控件，与右上角的图层按钮相对；通用设置作用于整个棋盘，不属于任何单独图层。控件固定在棋盘视口内，不随棋盘内容滚动，不遮挡底部进度条。
- 第一组按钮互斥选择格子大小模式，分别为固定数值、相对比例、自适应。

| 模式 | 按钮文本 | 格子边长 | 调节方式 |
| --- | --- | --- | --- |
| 固定数值 | 当前固定边长加 `px`，例如 `16px`。 | 用户指定的像素值，与录像本身的格子大小无关。 | 设置浮层提供几个像素值预设和一个 input，自定义固定边长。 |
| 相对比例 | 当前比例的百分比，例如 `100%`。 | `ms-toollib` 提供的录像原始格子边长 `pix_size` 乘以用户指定比例；同一比例在不同录像中可能对应不同像素值，比例为 1 时使用录像原始大小。 | 设置浮层提供几个百分比预设和一个 input，自定义相对比例。 |
| 自适应 | `pi-expand` 图标，悬停提示模式名称。 | 使用 `MinesweeperBoard` 的 `size="auto"`，由依赖根据可用空间调整格子大小。 | 不自行实现动态尺寸计算。 |

- 固定数值和相对比例均沿用图层按钮的设置入口交互：按钮左侧紧贴三点 handle，点击后在左侧打开交互式 tooltip 设置浮层，按钮本身用于选择模式。选择预设或编辑 input 更新对应设置，按钮文本同步显示新值；浮层沿用现有外部点击及 Esc 关闭行为。
- 模式、固定边长和相对比例属于 Analyzer 设置，保存到本目录的 localStorage 配置；切换模式保留各自的数值，重新打开或刷新恢复设置。录像原始 `pix_size` 随当前录像读取，不作为用户设置保存。
- 所有图层共用同一个棋盘的实际格子大小。轨迹仍按录像原始 `pix_size` 将像素坐标转换为格子坐标，再由依赖按实际尺寸绘制；内置 marker 也使用棋盘的实际格子大小，不因模式切换而错位。
- 调节大小和切换模式不修改进度或播放状态，不重置图层设置，不重新请求或解析录像。固定数值和相对比例模式空间不足时保留棋盘视口内部滚动。
- 默认模式为自适应，固定边长默认 `32px`，相对比例默认 `100%`。像素预设暂为 `[16, 24, 32, 48]`，百分比预设暂为 `[50, 100, 150, 200]`，数组位于 `BoardSizeControls.vue`，后续由用户调整。
- 自定义数值使用项目 `InputNumber`：固定边长最小 1px，百分比最小 1%，步长 1，不设置最大值；允许自定义小数。编辑空值或非法值时不写入设置，失焦时恢复或限制到有效范围。修改非当前模式的数值不会自动切换模式。
- `BoardSettingsControl.vue` 抽取原图层按钮的浮层和 handle 行为，供 `BoardLayerControl.vue` 与 `BoardSizeControls.vue` 共用；不复用弹窗播放器内部组件。右侧列上方放图层按钮，下方放尺寸按钮；空间不足时控件列独立滚动，自适应棋盘视口不显示滚动条。

### 全局棋盘图层

- `useReplaySource.ts` 随录像对象变化读取并缓存 `board` 快照，播放定位不重复读取或修改底盘；录像更换或卸载时清除当前底盘引用。
- `board[row][column]` 中 `-1` 为雷，`0` 为空，`1` 到 `8` 为邻雷数，直接使用依赖提供的数字，不在前端重新推算。
- 在 `foreground` 插槽中向全局 `BoardForeground` 显式传入真实底盘，显示所有数字和雷，包括失败录像中未打开的格子。
- 全局图层默认关闭，位于锁定显示的已打开前景图层之下，共用已打开局面的背景和当前实际格子尺寸。开启时叠加显示，已打开层的空白区域可透出全局层。
- 右上角的地球图标切换全局图层，提供本地化名称提示和 `aria-pressed` 状态。开关由页面保存，切换布局不重置，隐藏时保留占位尺寸。
- 全局内容与播放时间无关；切换显示不跳转、不暂停，不重新请求或解析录像。点击图标左侧的三点 handle 打开设置浮层，提供显示开关和不透明度滑块。

### 已打开棋盘图层

- `App.vue` 持有唯一的 `useReplayPosition.ts` 实例，随录像对象和共享 `currentMs` 更新，统一设置解析对象的 `current_time`，再读取 `game_board` 快照。
- 普通位置使用 `currentMs / 1000`；终点使用 `Infinity` 选中最后一个事件，避免时长加偏移的浮点边界遗漏最后一步。初始时间 0 的局面也以依赖的定位结果为准，不强行改成全未打开。
- `BoardPanel.vue` 不定位或修改解析对象，只将局面快照传给唯一的 `MinesweeperBoard`。已打开 `BoardForeground` 不显式传入 `board`，由棋盘依赖将上下文中的 `game_board` 转成前景编码，保留数字、旗帜和失败后的雷等符号；未打开格对应透明空白，背景表示当前开闭状态。不自行过滤或推算。
- 格子大小由单个棋盘统一提供，各图层随大小模式同步调整；固定数值和相对比例模式空间不足时在棋盘视口内滚动，图层按钮、通用设置及底部进度条不随棋盘滚动。
- 已打开图层锁定显示，不透明度固定为 100%，没有开关、设置按钮或可修改的显示状态；切换布局不影响显示。
- 鼠标轨迹统一承载线条和按键 marker，保留一个图层入口。

### 概率棋盘图层

- `useReplayPosition.ts` 在设置 `current_time` 后同时读取 `game_board` 和 `game_board_poss` 快照，保证两者使用同一次定位。播放、跳转、回退、终点和循环均同步更新；卸载录像时同时清除两份快照。
- 使用依赖的 `BoardProbability`，在 `foreground` 插槽中叠加于已打开图层之上。显示未打开且未标旗格子的雷概率百分比（0 安全、100 为雷），过滤和文字渲染由依赖负责，不自行计算概率。
- 概率图层默认开启，右上角百分比图标独立控制开关；隐藏不影响背景和已打开图层，切换布局保留开关，不修改时间、播放状态或重新加载录像。概率按真实 `game_board` 判断哪些格子显示文字。
- 与 VideoPlayer 共用 `videoPlayerConfig.probabilityColorScheme` 和 `PiecewiseColorScheme`，以概率乘以 100 映射配色。配色修改后自动更新渲染；不共享 VideoPlayer 的 `showProbability` 开关，不新增另一份配色存储。
- 点击图标左侧的三点 handle 打开设置浮层，包含显示开关、不透明度滑块和公共 `ColorSchemeSetting`，限制分界点为 0 到 100，实时修改共享配色。

### 鼠标轨迹

- 当前安装的 `@putianyi888/vue3-minesweeper-board 0.6.1` 提供 `MouseTrace`、按键状态配色、线宽和 `[startIndex, endIndex)` 显示范围。按键事件并入轨迹，`lc`、`lr`、`rc`、`rr` 默认使用库内置 marker 样式；整个图层仍默认关闭，各类 marker 可关闭并保留样式。
- 输入坐标为格子单位：录像像素坐标除以录像的 `pix_size`，保留小数，不用当前渲染尺寸换算录像坐标。组件内部随棋盘实际格子尺寸绘制。
- 设置项包括图层不透明度、拖尾长度（单位 s）和遮罩不透明度。两个不透明度分别保存：图层不透明度沿用现有 CSS `opacity`，默认 1；遮罩不透明度传给 `MouseTrace.opacity`，控制其黑色背景，默认 0.5。
- 鼠标轨迹位于概率层之上、光标之下，默认关闭；开关独立于其他图层，布局切换保留。
- 拖尾长度默认 1s，按录像时间计算，显示当前时间之前指定秒数内的轨迹，起点不早于录像开头；无限长度表示保留从录像开头至当前时间的全部轨迹。播放倍率不改变拖尾覆盖的录像时长。暂停、跳转、拖动和循环时均随共享 `currentMs` 更新，不使用独立计时器。
- 时间窗口两端均包含边界事件；端点落在两个时间戳之间时，采用不大于端点的最近时间戳，计入左侧、不计入右侧。因此左端点可以包含时间窗口外侧的最近事件，右端点只包含内侧事件。同时间戳的事件取最长轨迹：窗口开头取该时间戳的最小事件索引，非播放状态下结尾取最大事件索引，并加 1 作为 `MouseTrace` 的排他 `endIndex`。
- 播放过程中，右端点优先以统一定位后 `ms-toollib` 提供的当前事件索引为准，不再扩展到该时间戳的最大索引，避免提前显示尚未到达的同时间戳事件。原事件索引与轨迹数组索引保持映射，不直接混用。鼠标轨迹只读取统一定位后的索引，不自行调用事件索引 setter；关键帧 workaround 由页面定位模块统一处理。
- 0s 拖尾不等同于隐藏轨迹：非播放状态下显示当前或其左侧最近时间戳的完整事件组及组内轨迹；播放状态下从该时间戳的最小索引显示至依赖提供的当前事件索引。
- 长度滑块通过分式映射覆盖 `[0, Infinity]`：归一化滑块值 `t` 在 `[0, 1]` 内，`t < 1` 时长度为 `t / (1 - t)` 秒，`t === 1` 时显式返回 `Infinity`，不将最右端限制为某个有限时长。反向映射为 `t = L / (1 + L)`，无限长度对应 1，默认 1s 对应 0.5；最右端显示无限标识而不是非有限数字输入值。
- 长度滑块使用可用的最高精度，不人为设置离散档位、固定小数步长或对计算结果取整；保留浏览器输入和 JavaScript 数值所支持的精度，显示格式化不改变实际长度值。
- `MouseTrace` 不接收时间戳，由 Analyzer 将当前时间和拖尾起点转换为 `[startIndex, endIndex)` 事件索引，保留原事件顺序。依赖支持的动作仅为 `mv`、`lc`、`lr`、`rc`、`rr`，其他鼠标动作 fallback 到 `mv`，保留位置、时间、状态和原事件索引，不因动作类型不受支持而丢弃轨迹点。
- `MouseTraceSettings.vue` 接入全部公开视觉 props：`color` 分别编辑 uu、du、ud、dd 状态的线色；`lineWidth` 以格为单位，默认 0.08；`opacity` 仍是黑色遮罩，不与图层 CSS opacity 混用。`events` 和 `startIndex/endIndex` 由录像及拖尾驱动，不作为手动样式覆盖统一时间。
- `markers` 分别设置开关、`shape`（circle/ring/cross/square/diamond）、`size`、`fill`、`stroke`、`strokeWidth`、`opacity`。大小和描边宽度以格为单位，初始样式沿用依赖默认值；颜色复用 BaseColorPicker，支持无颜色。禁用只向依赖传 false，重开恢复用户样式。保存到 `traceAppearance`，页面组件和独立视频 render 读取同一份 props 映射。
- 当前依赖没有 lineDash、lineDashOffset、lineCap、lineJoin 等可设置 props；额外线型按 [上游请求](./MOUSE_TRACE_LINE_STYLE_REQUEST.md) 等待公开接口，不添加无效控件或本地绘图实现。
- `mouseTrace.ts` 提取事件为普通数据快照，读取后释放 record、event 和 mouse 的 WASM 包装对象；快照通过页面 computed 按录像对象缓存，布局切换和播放不重新提取。事件时间用 `(record.time + video_start_time) * 1000` 转换至共享毫秒时钟。
- 拖尾及原事件索引映射复用项目已有 `d3-array` 的二分查找。`useReplayPosition` 在同一次设置录像时间后同步读取当前事件索引，棋盘和轨迹不各自修改解析对象。
- 关闭轨迹时不挂载轨迹 Canvas，设置值仍保留；已打开局面、概率层和棋盘尺寸不受影响。轨迹浮层提供中英文本地化，长度滑块使用原生 `step="any"`，显示格式化不改变实际长度。

### 光标图层

- 已实现 `BoardCursorLayer.vue`，默认开启，位于所有棋盘图层之上；显示录像当前时刻的鼠标光标，与鼠标轨迹、按键事件独立，不替代真实浏览器光标。
- 右上角提供独立图层开关，沿用三点 handle 和左侧交互式设置浮层；设置项为形状互斥按钮组和大小滑块。形状按钮使用对应图标、名称提示和选中状态，同一时间仅选中一种形状。
- 形状支持圆点、Windows 默认箭头、圆环和十字，默认圆点。圆点、圆环和十字的热点为 SVG 中心，Windows 箭头的热点为尖端，切换形状不移动定位点。
- 大小指 SVG 元素边界框的绝对像素尺寸，默认 `32px`，范围 `4px` 到 `40px`（包含两端），步长 `1px`。不按格子大小缩放，也不代表内部图形本体的尺寸；默认圆点的几何直径为 6px，保留明显留白。
- `useReplayPosition.ts` 在统一设置 `current_time` 后读取 `x_y`，按录像 `pix_size` 转换为连续格子坐标，保存普通快照并立即释放 WASM 坐标包装对象；无效数值或越界坐标隐藏，录像卸载时清空位置，合法原点仍显示。
- `BoardCursorLayer.vue` 在现有单个棋盘的 `foreground` 中叠加，使用插槽提供的实际 `size` 将格子坐标换算为像素位置；三种大小模式下均保持对齐，SVG 自身大小不变。不拦截鼠标交互，不影响棋盘布局。
- 播放、暂停、跳转、拖动、回退及循环时同步页面已有的定位快照，不新增时钟或自行定位解析对象。
- 光标开关、形状和大小保存到 Analyzer localStorage；当前位置不持久化。修改设置不改变进度、播放状态或其他图层，不重新请求或解析录像。

### 色阶编辑

- 公共 `ColorSchemeSetting` 提供逐区间编辑，支持修改分界点、颜色、拆分区间及删除分界点；色阶预览条和数值样本已移除，功能按钮位于顶部。显示顺序始终按区间数值递增，不改变底层阈值与颜色的顺序。
- 区间的两个端点使用无边框输入框，相邻区间共享同一分界点的编辑值；最外侧值域端点由 min/max 控制，以只读输入框显示。删除按钮紧邻对应数字。颜色控件最大宽度 96px、高度 18px。
- 保留现有取色逻辑，以不等式显示区间：递增时 `下限 < x ≤ 上限`，递减时 `下限 ≤ x < 上限`；恰好等于阈值时属于该阈值之前的颜色区间。有限值域的最外侧端点包含在区间内，使用 `≤`，不再使用圆括号和方括号。
- 切换区间开闭按钮采用空心/实心端点组成的区间图案，同时反转 `thresholds` 和 `colors`，切换阈值处的颜色归属，非阈值处的配色保持不变，显示顺序不变。不新增独立开闭配置；少于两个不同阈值时不能通过反转表达方向变化，禁用该按钮。
- 使用公共 `BaseColorPicker`，外观由调用方的 class/style 决定。无颜色是选择器的特殊模式，清空时返回 `rgba(0,0,0,0)` 字符串；现有透明色同样显示为无颜色，不改写传入值。配色和存储仍使用 `colors: string[]`，不增加 null 数据类型。

- Analyzer 概率图层的设置浮层已接入该公共色阶编辑器，修改共享配色。

### 设置存储

- `store.ts` 参照 `src/services/store.ts`，使用 VueUse `useLocalStorage` 和 `mergeDefaults: true`，独立存储键为 `video-analyzer-config`，不放入 services 或 VideoPlayer 的存储模块。
- 已实现的所有可编辑设置都持久化：布局选择、各布局分割比例，全局/概率/轨迹的开关和不透明度，轨迹拖尾长度、遮罩不透明度、线宽/线色和 marker 开关/样式，光标开关、形状和大小，播放倍率和循环模式，格子大小模式、固定边长和相对比例。后续新增设置除明确约定的共享项外也沿用该配置。
- 共享概率配色仍通过原有 `video-player-config` 保存，不复制到 Analyzer 配置。
- 文件解析计数器的有序行配置、公式、逐行数字格式、采样模式及后续确认的展示设置由 Analyzer 独立维护，接入网站包装页的 `video-analyzer-config`；不读取、修改或同步 VideoPlayer 的 `custom-counter-config`，不沿用其含字符串拼接的默认表达式。排列、公式、格式和采样模式持久化，不保存录像对象、求值结果、采样数据或播放进度。
- 无限拖尾在 JSON 中存为字符串 `infinite`，页面转换为 `Infinity` 供轨迹使用，避免普通 JSON 序列化将其变为 null；有限长度保存原数值，不量化。
- 新建页面播放控制器时恢复保存的倍率和循环模式，用户修改后同步写回；时钟本身不依赖存储。重新打开默认暂停，从录像开头开始，区间恢复为整份录像。
- 不保存录像相关状态：录像 ID/对象、当前进度、时长、当前事件索引、局面快照、光标位置、播放/暂停状态和区间端点。录像 ID 继续由 URL 决定，区间信息仅在当前页面控制器内共享，不跨录像恢复。

### 播放时钟与进度条

- `components/VideoAnalyzer/App.vue` 创建唯一的 `usePlayback.ts` 控制器，其生命周期独立于布局和棋盘组件，不创建全局单例。
- 时钟不依赖 `ms-toollib`、棋盘渲染库或原有弹窗播放器；时长可来自数值、ref 或 getter。
- 使用 VueUse 的 `useRafFn` 管理动画帧及作用域清理，按实际经过的时间推进，而非每帧累加固定步长。
- 共享状态为 `currentMs`、`durationMs`、`isPlaying`、`playbackRate`、`loopMode`、`canPlay`、`rangeStartMs`、`rangeEndMs`；控制接口为 `play()`、`pause()`、`seek(ms)`、`setPlaybackRate(rate)`、`setLoopMode(mode)`、`beginSeek()`、`endSeek()`、`setRangeStart()`、`setRangeEnd()`。`loopMode` 为 `'none' | 'range' | 'all'`，不保留独立的循环布尔开关。
- 当前控制器通过 `playback` prop 传给棋盘、底部进度条及时间轴，读取同一份 `currentMs`、`durationMs`、`rangeStartMs`、`rangeEndMs`，不维护独立的区间副本，也不通过互相监听来同步。进度滑块使用原生 range，按钮使用项目基础组件，支持中英文本地化。
- 新建页面默认暂停，首次使用默认原速且不循环；有保存设置时恢复倍率和循环模式。时间限制在 `[0, durationMs]` 内。不循环时自然播放到终点暂停；终点点击播放从头开始。
- 进度跳转保留原播放状态。不循环和全部循环定位至终点时先显示终点，下一次时钟更新停止或回绕；区间循环播放时跳转到区间外，立即回到区间开头。
- 拖动期间保留播放状态但不推进时间，释放后从所选位置继续；原本暂停则保持暂停。释放、取消、窗口失焦或组件卸载时结束拖动并重建时间基准。
- 全部循环按整份录像时长回绕，保留延迟帧越过终点的时间量；切换循环模式不会自行开始播放。
- 不循环、区间循环和全部循环使用一个互斥按钮组，首次默认不循环，之后恢复保存的模式，提供本地化提示及选中状态。播放期间（含拖动时）禁用模式切换，控制器同样拒绝切换；暂停后可切换。
- 区间循环播放时，只要 `currentMs < rangeStartMs` 或 `currentMs > rangeEndMs`，立即回到区间开头并重建时间基准，不保留越界时间量、不使用取模；正常推进、倍速、延迟帧、手动跳转或拖动均遵守此规则。暂停时可定位到区间外，暂停期间也可修改端点或模式；恢复播放时，若位置在区间外则立即回到区间开头。恰好等于区间端点时保留位置，后续越界再回绕。
- 加速和减速只切换预设倍率的相邻档位，到达两端后禁用对应操作，不循环切换；原速恢复为 `1x`。播放中变速保持进度连续。
- 区间开头默认 0，区间结尾默认 `durationMs`；录像加载或时长变化时恢复默认端点。布局切换保留选定区间。
- 两个按钮分别将当前 `currentMs` 设为区间开头或结尾，并显示以秒为单位的 `[开头, 结尾]`。设置不跳转进度、不改变播放/暂停、倍速或循环状态。
- 进度条轨道上显示非默认区间端点：开头标记位于轨道上方，结尾标记位于下方；端点恢复到录像开头或结尾时隐藏对应标记。标记不拦截进度条的点击或拖动。
- 设置开头后若开头大于结尾，则将结尾重置为录像结尾；设置结尾后若结尾小于开头，则将开头重置为录像开头。严格比较顺序，端点相等时保留。
- 没有有效时长或正在区间循环播放时禁用两个端点按钮，控制器同样拒绝播放期间修改区间循环的端点；暂停后可修改。区间不限制普通播放或全部循环，不自动启用区间循环。
- 零长度区间（`rangeStartMs === rangeEndMs`）启用区间循环时，播放按钮禁用且控制器拒绝播放；仍可跳转、拖动、修改端点或切换模式以解除限制，不影响非默认端点标记。不循环和全部循环模式仍可正常播放。

当前预设倍率位于 `usePlayback.ts`，后续由用户调整：

```ts
export const playbackRates = [0.25, 0.5, 0.75, 1, 1.5, 2, 4, 8];
```

## 功能规范与后续

### 计数器、时间轴与分析

- `CounterPanel.vue` 与时间轴共用页面层 `prepareCounters` 返回的 Map；引用同一 key 的所有轨道读取同一份采样结果，不重新求值或定位 WASM。时间轴使用多个轨道 plot，每个 plot 可容纳多条轨道。网站信息由包装页的 info slot 独立展示。
- 继续使用页面统一时间及录像状态，不各自运行时钟或修改解析对象的当前位置。
- 时间轴已经与进度条共享区间信息，区间标记直接读取控制器端点。需要修改端点时调用控制器接口，遵守端点颠倒重置和区间循环播放期间禁止修改的规则，不另设区间状态。
- 所需分析计算按需求添加本目录内的 TypeScript 模块，不提前建设通用分析框架。

### 计数器（已实现，网站信息独立展示）

- 用户确认现有 `KeyDynamicParams` 的数据已足够，动态变量为 `time`、`path`、`bbbv_solved`、`left`、`right`、`double`、`lce`、`rce`、`dce`、`flag`、`op_solved`、`isl_solved`、`mouse_state`。另支持录像静态变量 `row`、`column`、`mine_num`、`pix_size`、`bbbv`、`op`、`isl`、`cell0` 至 `cell8`、`zini`、`hzini`、`rtime`、`level`、`mode`，共 34 个变量。可使用 `expr-eval` 自带函数；其他变量直接显示错误，不补取其他 getter。原完整指标请求草稿停止推进，不再等待该接口，关键帧上游同步问题仍待修复，但已按用户确认的 workaround 接入。
- `time` 使用事件记录的原始秒数，`path` 使用事件记录的原值，其余动态变量取自对应 `KeyDynamicParams`。21 个静态字段在读取该录像事件数据时从录像 getter 各读取一次，以原值加入每个事件的求值上下文；`rtime` 单位为秒，不使用 `rtime_ms` 替代，也不把静态 getter 用作动态事件字段。事件时间通过 `(record.time + video_start_time) * 1000` 与页面进度对齐；原始事件快照保留数组顺序和索引，采样阶段再按毫秒去重，不修改解析对象的时间或事件定位，读取后释放 WASM 包装对象。 连续采样补齐的毫秒只修改采样时间戳，表达式的 `time`、其余字段和来源事件索引全部沿用此前最近原生事件，不把 `time` 改为当前采样时间。
- 当前计数器实现范围包括独立数值配置、按列排布、逐行菜单和添加/移动/公式编辑弹窗，以及连续/按键/局面变化采样、每毫秒合并与时间插值、通用设置、JSON 导入导出。菜单包含在上方添加、在下方添加、移动、编辑和发送到 plot；无 plot 时禁用发送。网站信息独立展示四行，专用接口已接入，不依赖计数器采样。原有录像软件类型和文件字节请求保持不变。
- 计数器只展示文件解析数据；网站录像信息已拆为独立的 `info` 插槽区域，区分数据来源，不用文件中的玩家标识代替网站上的录像主人。网站包装页默认提供四行 WebsiteReplayInfo，调用方仍可通过 `#info` 替换。
- 宽容器的信息和计数器在原面板中上下排列、自动分配高度；窄容器的信息放在工作区最上方，计数器位置由布局预设决定，见“页面布局”。
- 信息按内容所需高度完整显示，不随计数器数据一起滚动；当前默认完整显示占位内容。
- 文件解析数据使用计数器区域扣除底部按钮后的可用高度，每行显示 key 和一个数字，采用较窄的列宽。按行顺序从上向下排列，当前列纵向排满后转到右侧下一列继续排列；列数过多时使用横向滚动条，不以纵向滚动代替续列。
- 调整面板大小或切换布局时，按新的可用高度重新排列，保持行的逻辑顺序和公式，不撑开整个面板。横向滚动仅作用于文件数据区域，不带动上方网站信息。

| 部分 | 数据来源 | 展示内容 |
| --- | --- | --- |
| 文件解析数据 | 当前站内录像经 `ms-toollib` 解析、分析得到的字段。 | 每行自定义表达式返回一个数字，使用与对应轨道相同的采样模式，按共享时间读取采样值或线性插值；可发送到时间轴的 plot，作为其中一条数据轨道。 |
| 网站录像信息 | 网站包装页已接入四行及一次性接口，展示录像 ID/上传时间、玩家/比赛 ID、录像名次及文件名。 | 接口返回完整模型字段，字段核对仍暂缓；浏览器展示由用户验收。 |

- 表达式仍使用 `expr-eval` 语法、工具函数和条件表达式，禁用 `assignment`，但最终产物必须是单一数字。每次求值后、格式化显示前检查 `typeof result === 'number'`，拒绝字符串、数组、布尔值和函数，不自动把数字字符串转换为数字；不能仅凭表达式解析成功或编辑时的一次求值认定后续结果均合法。
- 允许 `NaN`、`Infinity` 和 `-Infinity` 作为数值结果，保留并显示，不使用 `Number.isFinite` 拒绝它们，也不当作求值错误或回退为 0。
- 配置采用有序行数组，每行保留 key、expression、format、samplingMode，format 为 `d3-format` 格式字符串，samplingMode 为该行与对应轨道共用的采样模式，独立保存在 Analyzer localStorage，不与 VideoPlayer 共用；key 同时标识该行并作为显示名称，不随移动位置或编辑公式改变，不设置独立名称字段。字段读取保留原值，不将 `undefined` 等情况回退为 0；解析、求值或结果类型错误直接在该行数值格子中显示错误内容，用户可通过条件表达式处理数据边界。

- 原先的整体编辑图标和与 VideoPlayer 一致的整表编辑界面不再作为本轮方案；改为每行左侧一个 handle，点击展开交互式 tooltip 菜单，菜单包含“在上方添加”、“在下方添加”、“移动位置”、“编辑”、“发送到 plot”。浮层使用项目已有方案，不因列区域滚动而被裁剪。

#### 采样点差分（已实现）

- 支持 `d(expr, n)`，参数可以是支持变量组成的任意合法数值表达式，不限于单个字段。定义为 `d(expr, n)[i] = expr[i] - expr[i - n]`，分别在两个采样点的上下文求值；步长 `n` 在当前采样点求值，必须为正整数，省略时为 1，非法步长直接显示错误。不是对时间求导，也不自动除以步长或时间差。例如 `d(left + right + double)` 为区间点击数，`d(bbbv_solved, 2) / d(time, 2)` 为跨两个采样点的区间 3BV/s。
- 步长按该行采样模式筛选、每毫秒保留最后一个符合条件事件后（连续模式还补齐空白毫秒）的有序采样点数量计数，不按时间长度计数，不使用被筛除的事件或每个播放帧作为前驱。差分先在采样点计算，再沿用现有的时间插值与数字格式化；计数器和引用它的数据轨道共用结果。
- 前驱不足时，差分返回 `NaN`，不补 0 或复制当前点。允许嵌套差分，如 `d(d(expr))`；每层作用于内层结果序列，二阶差分的前两个采样点返回 `NaN`。嵌套可以使用不同步长，例如 `d(d(expr, 2), 3)` 的前五个采样点返回 `NaN`。
- 保留差分运算产生的 `NaN` 和正负无穷，不过滤、不替换。原有变量白名单、数值结果要求及错误显示规则不变，表达式解析或求值错误仍作为错误展示。
- 求值依赖采样点索引，不依赖上一次函数调用或播放方向；条件表达式中跳过某次 `d` 调用不会改变其他采样点的含义。播放、定位、倒退和编辑预览在同一采样点应得到相同结果。
- 已接入 `counterDifference.ts`，复用 `expr-eval@2.0.2` 解析后的指令结构，只适配 `d(expr)` / `d(expr, n)` 的惰性求值；条件分支、运算符及其他函数由原库处理，不用正则解析参数，不引入另一套表达式语法。该模块依赖内部指令接口，升级依赖时需复查并运行测试，调查及边界见 `COUNTER_DIFFERENCE.md`。编辑弹窗提供 VitePress 表达式参考链接，差分、采样点步长、区间速率及嵌套说明统一在文档维护。

### 自定义事件（时间轴首版已实现）

#### 求值与事件判定

- 每种自定义事件由一个 `expr` 定义，覆盖整份录像的所有原生事件类型，不按按键或局面变化筛选。分辨率与计数器“连续采样”一致：恢复整数毫秒后，每毫秒只保留原生事件数组中索引最大的事件，无原生事件的毫秒沿用此前最近原生事件的全部字段（包括 `time`）再求值和判定。使用 `Math.round((record.time + video_start_time) * 1000)` 与现有页面时间坐标对齐，不另设亚毫秒分组或容差。播放、暂停和可视时间窗的变化不改变事件是否发生。
- `expr` 的支持范围与计数器完全一致：使用相同的 `expr-eval` 语法、运算符、工具函数、条件表达式、34 个支持变量及禁用 `assignment` 的配置，支持 `d(expr)`、`d(expr, n)` 及嵌套差分。差分步长按自定义事件连续采样后保留的毫秒采样点数量计数，不沿用某个计数器行的按键或局面变化采样序列；前驱不足仍返回 `NaN`。不为自定义事件另设一套表达式语言或不同的函数支持范围。
- 表达式结果必须为 `boolean`、`number` 或 `string`，发生判定采用 JavaScript 原生布尔转换 `Boolean(value)`，不使用计数器的单一数字结果约束，也不将结果先转为显示字符串后再判断。
- `true`、非零数字（包含正负无穷）和非空字符串判为发生；`false`、`0`、`-0`、`NaN` 和空字符串判为未发生。字符串 `"false"`、`"0"` 和仅含空白的字符串仍为非空字符串，不额外解析或去除空白。
- 表达式解析或求值错误、非法返回类型均视为事件不发生。只有 boolean、number、string 结果参与原生布尔转换；数组、对象、函数、`null`、`undefined` 等不能凭 truthy 值判为发生，也不自动转换为允许的类型。错误采样与正常未发生采样一样参与持续段的结束判定，不跳过错误点，不沿用上一次发生状态，不中断其他采样点或其他自定义事件的计算。计数器原有的错误显示规则不变。
- 后续添加更多涉及原生事件的字段支持，计数器与自定义事件保持相同的表达式变量支持范围；具体字段名、含义及单位随需求确认后补充，不在当前计划中提前假定额外字段已由依赖暴露。
- 同一毫秒先保留最后一个原生事件，再求值和作布尔判断，不先筛出结果为真的事件；该毫秒最后一次结果为假时，前面为真的事件不产生脉冲或持续状态。无原生事件的毫秒向前 fallback，每毫秒仍独立求值；来源事件索引和全部字段（包括 `time`）保持原值，不构造假值。自定义事件统一采用该规则，不受任意计数器行选用的采样模式影响；可复用连续采样的事件选择逻辑，但不能使用计数器的数值求值结果替代事件表达式。

| 类型 | 一次事件的定义 | 时间轴显示 |
| --- | --- | --- |
| 持续性事件 | 一段在保留的毫秒采样点顺序上连续判为发生的采样记作一次事件；代码中的结束边界取首次未发生的采样，该采样不属于持续段，后续再次发生时记作新事件。无事件的毫秒不构造额外的未发生采样。 | 用线段表示，使用该种事件的颜色和 line style；绘制终点取该段最后一次发生的采样。录像末尾仍发生时，持续并绘制到录像结束。 |
| 脉冲性事件 | 每一个判为发生的毫秒采样点分别记作一次事件，同一种自定义事件每毫秒最多一次。 | 在对应的整数毫秒时间位置使用 marker，使用该种事件的颜色和 marker style。不同种自定义事件仍可在同一毫秒分别发生。 |

- 持续段的代码结束边界和渲染终点分别保留，不用最后一次发生的采样替代首次未发生的判定边界，也不把首次未发生的采样画入事件线段或持续过程中的鼠标轨迹。录像末尾没有未发生的采样时，以录像结束作为该段结束及绘制终点。
- 按已确认的持续定义，不存在零长度持续段，不另设零长度持续段的展示分支。每种自定义事件在时间轴占据独立一行，不存在事件行之间的重叠冲突，也不增加合并、堆叠或避让机制。

#### 布局与设置

- 时间轴区域从上到下排列：顶部时间轴刻度栏、自定义事件行、数据 plot。自定义事件主要由时间轴区域负责，不进入 plot 数组，不通过计数器的“发送到 plot”加入，不参与 plot 的共用 y 轴计算。
- 每种自定义事件占据固定 24px 高度的一行，轨道之间紧密排列、无分割线，每行有独立水平轴线。事件轨道整体与下方数据 plot 之间保留一条分割线。行开头显示该事件的 key，行末尾显示设置按钮，中间绘制持续线段或脉冲 marker。固定行高与可拖动调整高度的数据 plot 分开，不提供事件行调高。
- Analyzer 的成组按钮使用紧贴排列，组内无 gap 或相邻按钮 margin。进度条按播放定位、区间、速度、循环模式划分功能组，保留组间间距；导出入口与其他功能组保持间距。
- 自定义事件行与顶部刻度栏、数据 plot 共用横向时间坐标及可视时间窗，缩放和平移后保持对齐；继续使用页面共享的播放位置及区间信息，不新增时钟或区间状态。设置按钮不触发时间轴平移或播放定位。

| 设置项 | 规则 |
| --- | --- |
| key | 事件的标识及行开头显示文本，添加/编辑均可修改；去除首尾空白后非空且在自定义事件内唯一，可与计数器 key 相同。 |
| 公式 | 在每毫秒保留的最后一个原生事件上求值的 `expr`，结果允许 boolean、number、string。 |
| 持续/脉冲 | 选择连续发生合并为一次，或每个发生的毫秒采样点分别记为一次。 |
| 颜色 | 该种事件线段或 marker 的颜色。 |
| marker style | 圆形、方形、三角形、菱形或叉形，绝对像素大小、不透明度；默认圆形 8px、不透明度 1。 |
| line style | 实线、虚线或点线，绝对像素线宽、不透明度；默认实线 2px、不透明度 1。 |

- 设置保存到 `analyzerConfig.customEvents` 有序数组，默认包含两个持续性事件：`left` 的公式为 `mouse_state in [4, 5, 6, 7]`，`right` 的公式为 `mouse_state in [2, 3, 5, 6]`；每个条目包含 key、公式、类型、颜色、marker 和 line 配置，默认颜色 `#e15759`。已有配置（包括空事件列表）保持不变。原生事件快照、表达式采样及生成的事件段不持久化，切换录像后依据新录像重新计算。
- 求值和事件分组按需求放入本目录的独立 TypeScript 模块，时间轴事件绘制复用 `vue3-plots` 已有能力，棋盘事件图层使用原生 SVG。具体样式选项实现前核对依赖接口；通用能力缺口按开发边界提出 feature request，不提前另建表达式或绘图框架。
- 添加事件按钮与添加 plot 按钮并排；添加打开弹窗，初始 key/公式为空，默认脉冲类型。每行右侧设置按钮打开同一编辑弹窗，删除按钮在弹窗内。取消不更新配置；公式错误允许保存，按既定规则判为未发生。拖动左侧 key 排序，保存改名时保持行位置；两个列表互不混排。
- 棋盘事件图层已接入，选择设置保存到 analyzerConfig.eventLayer；时间轴事件改名同步更新选择引用，删除清理对应引用。后续扩充的事件字段仍待确认。

#### 棋盘事件图层（已实现，浏览器验收待完成）

- 在棋盘区域新增事件图层，使用原生 SVG 实现，叠加在同一个 `MinesweeperBoard` 的前景中，沿用实际格子大小及录像坐标转换，不另建棋盘或播放时钟。事件图层位于光标图层之下、其他图层之上；光标仍为最上层。
- 图层设置通过多选选择时间轴中已经定义的自定义事件，可同时展示多种事件；选择列表来自时间轴的事件配置，不在棋盘内复制 key、公式或样式设置。事件表达式、类型、颜色和样式在时间轴端修改后，棋盘使用同一份配置及判定结果。
- 脉冲性事件在该毫秒保留的原生事件鼠标位置绘制 marker，使用时间轴中设置的 marker style 和颜色。持续性事件使用 line style 和颜色绘制事件持续过程中的鼠标轨迹，并以箭头标记轨迹方向；不再仅绘制与时间轴相同的水平线段，不使用 `MouseTrace` 的 Canvas marker 代替该 SVG 图层。
- 图层默认关闭，默认不选择任何事件。展示的时间范围属于图层设置，可选“全局”（整份录像，默认）或“当前时间点及之前”（不展示未来部分）。图层开关、多选、时间范围及箭头设置按 Analyzer 的既有原则保存到 localStorage，事件采样和 SVG 路径随录像重新计算，不持久化。
- 持续轨迹使用持续段内所有原生事件的鼠标点，按原事件索引顺序连接，不按毫秒去重，保留同一毫秒内的移动路径。事件是否发生仍按每毫秒最后一个原生事件判定；持续段的代码与渲染终点仍遵守已确认的边界规则，不将首次未发生事件的鼠标点接入轨迹。
- 方向箭头的密度和外观可在图层设置中自定义：间距按渲染后的轨迹弧长计算，默认 32px；箭头大小为绝对像素，默认 8px；形状可选实心三角（默认）或开放箭头。颜色和不透明度继承对应事件的线条设置。各持续段独立布置箭头，方向沿原生事件顺序；静止点不产生方向箭头，非零轨迹短于设定间距时在末端显示一个箭头。
- 本图层仅用于页面分析，不进入视频导出。现有导出的其他图层、光标及鼠标轨迹行为不变；不将“导出与界面一致”的要求扩展到该事件图层，也不为它增加 SVG 栅格化或 Worker 导出接口。

### 时间轴、plot 与轨道

首版已接入数据轨道；plot 只支持数据轨道，自定义事件由上方独立事件行显示。以下为已确认规范，浏览器交互由用户运行组件测试验收。

- `analyzerConfig.timeline.slots` 保存两层轨道数组，`slotSettings` 使用同顺序的数组保存名称和高度，排序时一起移动。不增加 plot ID 或轨道去重映射。
- 默认 plot 高度 160px，调高最小高度 80px，周围 plot 高度保持不变。顶部刻度栏在时间轴内部纵向滚动时固定，plot 内容可内部纵向滚动。
- 可视时间窗在页面内独立保存，初始覆盖全部录像，缩放最短窗口为 1ms。各布局共用该窗口，切换录像后重置，不保存到 localStorage。普通滚轮以指针位置为缩放锚点，Ctrl/Cmd 滚轮不接管；绘图区拖动使用 `beginSeek`/`endSeek` 保持播放状态。

- 时间轴区域顶部为时间轴，其下为已接入的自定义事件行，再下方以数据轨道 plot 作为纵向排列的布局单位，替代原来的“每个布局单元仅一条轨道”机制。plot 是容纳数据轨道的应用数据结构，不是 Vue 插槽；每个 plot 允许容纳多条数据轨道。
- 时间轴的数据结构是 plot 的有序数组，每个 plot 本身是轨道的有序数组，即两层数组，而不是按轨道 key 索引的 Record、Set 或 `{ tracks }` 包装对象。空 plot 为 `[]`。plot 内及跨 plot 均不按 key、公式或轨道内容去重；相同轨道可以重复出现，数组中的每个条目分别参与绘制、图例及悬停显示。plot 名称和高度等展示配置的存放方式在实现时确定，不改变 plot 为轨道数组的结构。
- plot 支持修改名称，名称纵向显示在 plot 左侧，不再用某条轨道的 key 充当布局单元标题。轨道本身仍按 key 关联原数据，key 显示在图例中，修改 plot 名称不修改轨道 key 或公式。名称及图例区域不参与横向时间坐标，顶部时间轴与各 plot 绘图区保持对齐。
- 时间轴默认有两个 plot，初始轨道分别为 `[Bvs, Ces]` 和 `[Mov]`，默认名称为 `Plot 1`、`Plot 2`，支持改名、添加和删除 plot；新添加的 plot 同样为空，不自动复制其他 plot 的轨道或加入默认轨道。默认 plot 配置仅用于尚无存储配置时，不覆盖用户已保存的 plot。
- 顶部时间轴、自定义事件行与下方所有 plot 内的数据轨道共用横向时间坐标，事件位置和数据变化按录像时间对齐；继续使用页面共享的播放时间和区间信息，不新增独立时钟或区间状态。
- 绘图采用 `@putianyi888/vue3-plots@0.7.0` 的 SVG 图层，数据轨道使用 `Line sampling="min-max"`，坐标轴和网格使用 `Axis`、`Grid`；抽稀只影响路径绘制，原始采样、差分、事件计算及精确悬停保留完整数据。事件、播放位置和区间标记叠加在相同时间坐标下，不引入另一套图表库或 Canvas。
- 同一 plot 内的所有数据轨道共用 y 轴，使用这些数据轨道整份录像的采样数据一起调用 `vue3-plots.getDataDomain` 计算数值范围、`getNiceTicks` 生成刻度；0.7.0 已修复大数组参数展开溢出，不再保留本地极值预汇总 workaround。不为每条轨道各设一份 y 轴，不以抽稀结果计算范围。不同 plot 可使用各自的数值范围；自定义事件行不参与数据 y 轴范围计算。不随播放位置或横向可见窗口重新取局部范围，不在 Analyzer 内自建范围扩展或刻度算法。横轴仍使用所有 plot 共享的时间范围。
- `vue3-plots` 由用户维护，通用绘图功能缺口按开发边界提交 feature request。NaN/Inf 的绘制表现以依赖为准，当前 `Line` 会过滤非有限点并连接剩余点；暂不请求断线能力，不在调用层改变绘制行为，实际效果不好时再讨论。原始采样及插值结果仍原样保留。
- plot 支持的轨道类型：

| 轨道类型 | 展示内容 |
| --- | --- |
| 数据轨道 | 在 plot 内绘制某个数据随时间的变化，与同 plot 其他数据轨道共用 y 轴。 |

- plot 仅容纳数据轨道，取消原来的 plot 内事件轨道计划；添加轨道的下拉框也只提供数据轨道。自定义事件的配置、分组及固定行高由独立事件区域负责，不复用 plot 的轨道条目结构。
- 初始横向时间窗覆盖完整录像。支持拖动平移，但只有缩放后才允许平移；全录像视图不显示范围外的空白时间。仅在顶部时间轴刻度栏内，滚轮用于横向时间缩放，各轨道同步使用同一时间窗；轨道绘图区、标题、图例和右侧控件等其他区域保留普通滚动行为。只在顶部刻度栏消费用于时间缩放的普通滚轮事件，不占用网页或浏览器已有快捷键，Ctrl/Cmd 加滚轮保留浏览器原生行为。
- 平移边界为录像时间边界 `[0, durationMs]`，整个可见时间窗必须位于该范围内，不显示首尾以外的空白时间。平移保持时间窗长度不变，窗口起点截断到 `[0, durationMs - 窗口长度]`，到达边界后不能继续向外平移；不以选定区间或轨道采样范围限制平移。
- 已确认按区域分配手势：顶部刻度栏拖动平移横向可见时间窗，轨道绘图区点击或拖动修改共享 `currentMs`；标题排序、边界调高及右侧控件均不触发平移或播放定位。平移不修改播放时间；定位继续遵循进度跳转/拖动后保留播放状态的规则。
- 每个 plot 的控件纵向排列在 plot 右侧，包括添加轨道、删除 plot。添加轨道使用下拉框选择轨道，每次选择都向当前 plot 追加一个条目，不因相同轨道已存在而禁止选择或省略添加；数据轨道按原计数器行 key 关联，不复制表达式。删除 plot 必须弹窗二次确认，取消不改变 plot 或其轨道；确认后删除该 plot 及其轨道关联，不删除原计数器行。
- plot 自动为其中的各条轨道分配颜色。图例位于 plot 名称右侧，为一个窄矩形，按轨道数组条目数量沿纵向均匀分割成小矩形；每块填充对应条目的轨道颜色，文本为该轨道的 key，不使用 plot 名称代替。相同 key 的重复条目各占一块图例，不合并；图例颜色与实际绘制颜色一致，空 plot 没有轨道图例。
- 自动配色采用 [Tableau 10 分类色板](https://d3js.org/d3-scale-chromatic/categorical#schemeTableau10)，固定顺序为 `['#4e79a7', '#f28e2c', '#e15759', '#76b7b2', '#59a14f', '#edc949', '#af7aa1', '#ff9da7', '#9c755f', '#bab0ab']`。仅需要固定色值数组，不为此单独添加配色依赖；浅色和深色主题保留相同轨道颜色，legend 文本按背景亮度选择对比文字颜色。
- 每个 plot 独立分配颜色。新增条目选择该 plot 当前使用次数最少的色板颜色，次数相同按色板顺序选择；前十条自然使用不同颜色，超过十条允许复用，不重新计算已有条目的颜色。重复 key 作为独立条目分别分配颜色，不建立 key 到颜色的映射。
- 颜色随对应轨道条目的展示配置一起持久化，新增、删除、plot 排序或改名、公式/采样调整、录像切换及刷新均不重配已有颜色。删除条目释放其颜色占用，后续新增可复用；失效 key 的条目仍保留颜色并计入使用次数，直到手动删除。不改变 plot 为轨道数组的结构，不保存采样数据。
- 点击 plot 内某条轨道的 legend，打开交互式 tooltip，菜单可移除该轨道。移除只删除该 plot 轨道数组中被点击的条目，不按 key 批量删除，不影响同 plot 或其他 plot 内同 key 的条目，也不删除计数器原行。
- 轨道引用的 key 失效时，保留数组条目、原有位置及对应 legend，不自动删除或压缩位置；不绘制该轨道、不参与纵轴范围计算及悬停交点求值，仍可从 legend 的 tooltip 手动移除。此规则也适用于计数器配置导入后原 key 不再存在的情况。
- 原有标题拖动排序及边界调高改为作用于 plot：左侧纵向 plot 名称作为排序 handle，拖动名称改变 plot 顺序；拖动 plot 上下边界调整整个 plot 的高度，不分别调整其中各条轨道的高度。边界调整优先沿用 `interact.js` 的默认行为；该库没有默认的相邻布局单元高度分配，因此仅更新目标 plot 高度，保持相邻 plot 高度，其他 plot 可随正常文档流改变位置。参考 [尺寸事件及示例](https://interactjs.io/docs/resizable/)。plot 名称、轨道关联、顺序及高度属于 Analyzer 设置，按已有持久化原则保存，不保存采样数据。
- 悬停时显示一条跨所有 plot 对齐的竖线，并在每个 plot 内分别显示各条数据轨道曲线与该竖线交点的值，用轨道 key 和对应颜色区分；读取原计数器行已有采样及插值结果，数字显示使用该行的 format，不随鼠标移动重新求表达式或定位录像。悬停时间与播放时间分开，悬停本身不修改 `currentMs`。每条数据轨道在同一毫秒只有一个采样点，不再产生同轨道的同时间戳竖直线段；同一 plot 内多条轨道各自的交点仍分别显示，不只选一条轨道的值。
- 计数器每行菜单原“发送到轨道”机制改为“发送到 plot”：通过下拉框从时间轴已有 plot 中选择目标，选项显示 plot 名称；实际发送该行 key 到所选 plot。时间轴通过 key 读取该行数值表达式，每次均向该 plot 的轨道数组追加条目，不再按 key 新建一个独立布局单元。遵守与计数器相同的单一数字结果约束，并与顶部时间轴、共享进度和区间对齐；同一 key 可在同 plot 或不同 plot 内重复添加，不去重、不合并。
- 数据轨道的数据是对原计数器数据的引用，通过行 key 关联，不保存公式、格式、采样模式或采样结果的独立副本。编辑计数器行后，轨道读取更新后的数据，不自行求表达式，也不另行推进页面时钟。计数器与数据轨道不共享设置弹窗，`CounterRowEditor.vue` 仅用于计数器编辑；未来如需轨道展示设置，其界面与计数器公式编辑独立，具体设置项按需求确定。
- 接入轨道时，将当前计数器内部的采样求值计算移到共同上层，按行配置与录像事件变化计算一次；计数器显示、轨道绘图和悬停取值读取同一份结果，不各自维护采样副本。
- 每行的采样策略允许用户自定义，移除原“每个事件采样”，添加“连续采样”；计数器按以下三种模式采样，数据轨道引用对应行的采样结果，默认仍为按键事件采样（包含按下与释放）。samplingMode 随计数器行配置持久化并参与 JSON 导入导出，采样结果不保存到 localStorage。采样模式入口仅放在计数器每行编辑弹窗中，不作为轨道设置项，也不从轨道打开该弹窗。

| 采样模式 | 采样位置 |
| --- | --- |
| 连续采样 | 每 1ms 采样一次，包含所有类型的事件；同一毫秒有多个事件时使用原数组最后一个，无事件时向前 fallback 到此前最近的原生事件。表达式全部字段（包括 `time`）和来源事件索引保持原值，仅采样时间戳使用当前毫秒。范围从首个可用原生事件开始，延伸至录像结束；首个事件之前没有可 fallback 的数据，不伪造快照。 |
| 按键事件采样 | 先筛选所有鼠标按键的按下和释放事件，再在每毫秒保留最后一个符合条件的事件。不要求局面发生变化；同毫秒内后续的鼠标移动不覆盖已筛出的按键事件。 |
| 局面变化采样 | 先筛选事件前后 `game_board` 内容发生变化的事件，再在每毫秒保留最后一个符合条件的事件；仅鼠标移动或其他指标变化不满足条件，也不覆盖该毫秒符合条件的事件。 |

- 录像原始时间精度已确认为毫秒，事件转换到页面时间坐标后使用 `Math.round((record.time + video_start_time) * 1000)` 恢复整数毫秒，仅消除秒与毫秒转换的浮点误差，不设计亚毫秒分组或额外容差。三种模式统一先按模式筛选，再按该整数毫秒合并，只保留每毫秒内原数组索引最大的符合条件事件。连续模式在毫秒合并后补齐事件之间及最后事件至录像结束的毫秒，其他模式不补齐。输出每个采样点使用对应的整数毫秒时间戳，使单条数据轨道的采样时间严格递增，不共用时间戳；不同轨道仍可以在相同毫秒各有一个点。源事件字段原样用于求值，不因时间转换或采样合并而改写字段。
- 所有相邻采样点统一按时间线性插值：`value = v0 + (v1 - v0) * (currentMs - t0) / (t1 - t0)`。t0、t1 与 currentMs 使用相同毫秒单位，v0、v1 为未格式化的表达式结果；t0 与 t1 不相等，不再维护同时间戳采样组或按事件索引插值分支，也不需要通过上游事件定位接口读取计数器值。
- 计数器及数据轨道的采样合并不改变原生事件数组、鼠标轨迹、按键事件标记或关键帧的顺序和数量；自定义事件另按统一的连续采样规则逐毫秒取最后一个原生事件或向前 fallback，不随计数器行模式改变。切换计数器模式不改变行 key、表达式、数字格式或页面播放时间，计数器及对应数据轨道同步使用新采样结果。
- 命中采样点时使用该点原值；采样范围之外保持最近端点值，不外推，只有一个采样点时保持该值。`NaN`、`Infinity`、`-Infinity` 不过滤、不替换、不改为保持左值，插值运算得到什么就保留什么，也不回退为 0。计数器与轨道采用相同规则，数字格式在取值或插值完成后应用。
- 当前实现以采样点必然存在为前提，不设计无采样点分支；暂不考虑错误端点的存在性，不为其增加专门的插值处理或验收。表达式错误在数值格子直接显示的既定要求保留，不影响 `NaN`、无穷值作为数字直接参与插值的规则。
- 数据轨道来自计数器行，可通过发送到 plot 或 plot 右侧下拉框加入，不去重；plot 顺序和高度可拖动调整，自定义事件不加入 plot。默认两个 plot（Plot 1 为 Bvs/Ces，Plot 2 为 Mov）、名称、Tableau 10 自动配色及条目颜色保留、轨道 legend 点击打开 tooltip 并移除当前条目、平移限制在录像时间边界内、失效 key 保留位置且不绘图、目标 plot 的下拉框选择、滚轮缩放、多交点全部显示及非有限值沿用依赖等规则已确定。
- 事件标记的展示不等同于事件定位；后续按索引跳转沿用“关键帧定位”的唯一入口，不由图层自行修改录像。

### 关键帧定位

- 已验证 npm `ms-toollib 1.5.19` 的 `events`、鼠标事件类型及可读写的 `current_event_id`。事件记录还提供时间、鼠标状态、前后局面及动态指标；不能仅靠时间区分同时间戳事件。
- 四种录像类的 `current_event_id` setter 未同步内部时间；用户已提交 feature request，后续确认了可先使用 workaround，撤销此前等待修复再实现的限制。
- 已实现 workaround：页面先设置共享 `currentMs`，统一定位模块先设置 `current_time`，再设置 `current_event_id`。棋盘使用对应事件的前置局面，npm 接口名为 `prior_game_board.game_board`（即需求中的 `prev_board`），概率使用同一前置局面的 `poss`；光标和轨迹读取选定事件索引。获取后释放事件及局面包装对象，不预先缓存全部关键帧局面。
- 同时间戳关键帧通过索引和前置局面作外观区分；计数器仍按时间插值，不改成按索引求值。普通进度跳转（包括相同时间）或播放推进清除覆盖，回到正常时间定位；仅保留当前位置的正常时间索引，以处理上游重复设置相同时间不撤销索引覆盖的行为。
- 关键帧时间沿用时钟的首尾截断，计时零点之前的按键可在 `currentMs = 0` 时按索引访问。区间循环播放期间的越界回绕规则优先，不在回绕后的时间上强制选择区间外事件。
- 上游同步接口修复后，再验证事件索引、时间、局面及动态指标，移除不再需要的 workaround。
- 关键帧包含所有鼠标按键的按下和释放事件，不以棋盘是否变化筛选；单纯鼠标移动不作为关键帧，不用固定时间步进替代关键帧。
- 同时间戳事件以 `ms-toollib` 事件数组的原始顺序为准，不能去重或合并；上一帧和下一帧必须保留该顺序，定位保留操作前的播放/暂停状态。
- 相邻关键帧按当前事件索引确定：上一帧为索引严格小于当前索引的最后一个按键事件，下一帧为索引严格大于当前索引的第一个按键事件。当前事件本身不作为相邻帧，不按时间戳大小判断；同时间戳的不同按键事件仍可依次访问。
- 对应方向没有相邻按键事件时，显示错误提示，不跳转、不循环，也不改变当前事件索引、时间或播放/暂停状态。

### 视频导出

- 全部导出和区间导出已接入验证首版；是生成可播放的视频文件，不是下载原始 EVF、AVF 等扫雷录像文件。实际成品待用户运行浏览器测试，不将单元测试通过视为画面与编码验收完成。
- 长期候选格式包括 GIF 等动图，画面、裁剪、倍率、冻结及恢复规则相同，格式自身的调色板和时间精度限制需明确展示；当前只接入视频容器，本阶段不实现 GIF。
- 两种导出共用渲染与编码流程，区间导出使用已有 `rangeStartMs`、`rangeEndMs`，增加起点状态还原、时间裁剪和终点处理。
- 零长度区间禁用区间导出，无论采用哪种循环模式；全部导出不受此限制。导出窗口中的区间选项及提交按钮已加入此限制。
- 仅导出棋盘画面，支持矩形局部裁剪，默认整盘。不包含进度条、图层或格子大小设置按钮、计数器、时间轴及棋盘周围留白，不随页面面板布局扩大导出范围。
- 导出选项使用 `top`、`bottom`、`left`、`right` 指定区域，单位为格，下标从 0 开始，四个端点均包含对应格子。默认 `top = 0`、`bottom = row - 1`、`left = 0`、`right = column - 1`；不允许越界或顺序颠倒，允许只导出一行、一列或一格。超出导出区域的光标、轨迹等直接裁切；区域属于当前录像信息，不跨录像持久化。
- 输出尺寸沿用导出开始时界面实际显示的格子大小，包括固定数值、相对比例和自适应模式；导出期间固定该大小，不随页面尺寸改变重新计算。画面宽高由选中格子数量及该格子大小确定，不提供独立改变分辨率或图层缩放的规则。
- 除棋盘事件 SVG 图层明确不导出外，导出效果与界面显示一致，使用导出开始时参与导出的图层开关、层级、不透明度、配色、轨迹拖尾和遮罩、光标形状与绝对大小，以及当前主题。区间起点保留按照正常显示规则应出现的起点之前的鼠标拖尾，不从区间起点重新积累；不能只录制鼠标轨迹的 canvas 而丢失其他参与导出的图层。
- 格式、帧率、质量等参数统一在导出选项中配置。优先采用成熟第三方库，尽可能支持更多格式；具体可选容器、编码器及浏览器支持范围根据依赖调查和实际能力确定，不预先限定为 MP4 或 WebM，也不将库支持视为所有浏览器都可用。导出设置沿用 Analyzer 的 localStorage 持久化原则，录像相关的空间裁剪和时间区间除外。
- 播放倍率直接采用进度条当前倍率，不另设独立的导出倍率。完整录像或选定区间仅输出一次，不采用当前循环模式；编码处理速度与输出视频的播放倍率是两个概念。
- 导出期间冻结全页面的用户操作及设置，禁止修改播放进度、倍率、区间、布局、图层和其他页面控件，仅保留导出进度显示与取消操作。正常播放不与导出过程并行推进；完成、取消或失败均解除冻结，恢复导出前的播放位置及播放/暂停状态，失败时显示明确错误通知，取消不输出未完成文件。
- 已接入 `mediabunny@1.61.3` 和 `minesweeper-board@0.6.1` 的主线程独立渲染器，编码器动态加载，已移除 modern-screenshot，仅提供视频，不接入 GIF。首版格式 MP4、WebM、MOV、MKV，默认 MP4、30 FPS、高质量；帧率 input 为 1 到 120。使用实际裁剪尺寸及帧率检测当前容器可编码的 codec，无可用编码器时明确报错，不自动改变尺寸或格式。格式/帧率/质量存入 Analyzer localStorage，裁剪区域每次打开默认整盘，不保存。
- `VideoExportControls.vue` 使用原生模态 dialog 阻止页面操作，导出期间只显示进度与取消；页面路由离开及参数更新在导出期间拒绝，卸载时中止。开始时暂停普通播放并固定实际 cellSize，结束后恢复位置及播放状态，取消不下载。`videoExport.ts` 逐帧等待编码背压，成品保存在 BufferTarget，未实现大型文件流式保存。
- 采样输出时间为 `index / fps`，对应录像时间为 `startMs + index / fps * playbackRate * 1000`；最终帧时长缩短到区间终点，不额外追加终点停留帧。小数格子边界按像素四舍五入，不改变 cellSize；某尺寸没有编码器支持时直接报错。
- 导出从已下载字节创建独立解析对象，不重新请求、不推进页面 `currentMs`，不逐帧更新可见棋盘、计数器和时间轴，不等待 Vue 或播放时钟。`boardExportFrame.ts` 通过公开独立 render 等待贴图解码，直接按背景、全局、已打开、概率、轨迹、光标顺序合成到裁剪后的编码 Canvas，应用各层不透明度；没有 DOM 截图或逐帧 requestAnimationFrame。全局层及 SVG 光标在一次导出中复用，逐帧 release，完成/失败/取消时 destroy 并释放独立 WASM 对象。格子大小取背景层公开的 cellSize，光标屏幕与导出共用热点坐标；进度约每 50ms 刷新并让出一次主线程响应取消，不按媒体帧间隔限速。编码使用实际输出参数优先探测硬件候选，缺失时回退普通编码，保留防丢帧的 quality 模式及必要背压。倍率仅决定成品时间与采样，硬件实际使用及提速幅度仍需实测，不承诺饱和全部硬件。首次贴图、SVG、半透明、非整数尺寸及实际性能仍需浏览器验收。独立渲染接口已由 0.6.0 满足；完整调查见 [棋盘视频与动图导出调查](./VIDEO_EXPORT_RESEARCH.md)。

- 原网站信息区域由调用方提供的 `info` slot 展示。站内 `VideoAnalyzerView` 提供四行网站信息及链接按钮；离线页面只将此 slot 替换为选择本地录像文件的控件，不新增顶部工具栏、独立文件信息面板或另一套分析布局。组件内部不固定网站标题、录像 ID 或 `--` 占位。
- 本地页面解析用户选择的 EVF、AVF、MVF、RMV 文件，保留现有分析及导出功能；单次只分析一份录像，可依次更换文件，不新增多录像并排比较。
- 独立入口不加载网站根 App、路由、登录、玩家缓存或任何站内 API。自动工作流打包为离线网页包，用户解压后双击主 HTML，即使首次打开时断网也能使用，不要求 Node、Python、本地 HTTP 服务或先在线缓存。
- 普通浏览器能力差异仍按现有规则处理：主线程导出按实际编码能力检测。Worker 并行导出已按用户决定移除；开发服务器可运行不代表 file:// 可运行。

- 公共输入优先采用已有 `ReplaySource`（data、filename、software），另有外部 loading/errorMessage；分析器自己持有和释放解析对象、唯一时钟、定位及采样结果。避免同时传入可变 WASM 对象与另一个导出数据源，导致生命周期或文件内容不一致。
- 源替换时暂停并重置播放位置、区间、关键帧覆盖和可视时间窗，释放旧解析对象并重算采样；保留普通设置。迟到的站内响应或本地文件读取不能覆盖后来选择的源，损坏或不支持的文件显示明确错误。
- 配置由包装页持久化并通过 `v-model:config` 传入，组件内部按实例持有状态。先保留当前默认值、JSON 格式和网站 localStorage key；本地页面使用独立 key。子组件，尤其 VideoExportControls，不再直接读取模块级 analyzerConfig 单例。
- 概率配色通过普通配置绑定传入；站内包装页继续绑定 videoPlayerConfig.probabilityColorScheme，本地页面使用自己的设置。保留已确认的站内共享规则，公共组件不导入网站用户 store。
- 通过 `v-model:exporting` 把导出状态提供给包装页。路由守卫留在站内页，本地页在导出期间禁止换文件；公共组件卸载时仍中止导出，不依赖 vue-router。
- 公共 VideoAnalyzer 已提供 `info` 插槽，位于独立信息区域，不放回 CounterPanel；网站四行信息及其他实际内容由调用方提供。沿用四区布局：宽容器与计数器共享面板并自动分配高度，窄容器信息置顶；公共组件不提供网站默认内容，未传 slot 时不占高度。
- 离线入口始终通过 `#info` 提供录像文件选择控件，复用项目已有文件选择能力；只选择一份 EVF/AVF/MVF/RMV，读取后构造普通 ReplaySource。文件选择区沿用 info slot 的宽窄容器位置，不复制 WebsiteReplayInfo、排行榜、比赛或外部分析链接。
- 通知、剪贴板所需的 local 设置，以及共享概率配色等轻量持久化配置，如需脱离用户 store，先抽到已有功能的专用设置模块并从旧路径重导出。避免引入第二套通知、剪贴板、主题或颜色实现。

### 离线构建与资源

- 调查及上游依据见 [离线构建调查](./OFFLINE_BUILD_README.md)。已使用 Vite 8 + vite-plugin-singlefile 2.3.3 内联主页面 JS/CSS，首次本地构建通过；真实 file:// 浏览器验收仍待完成。
- 使用独立 `vite.offline.config.ts`、单一 HTML 输入和独立输出目录，例如 `dist-offline-analyzer`，不覆盖网站 dist。共享必要的别名、Vue/WASM 配置和 CSS，不继承网站部署地址、公共静态大目录、部署脚本或 `.gz` 输出。
- 离线构建将主线程 WASM 内联为可直接解码的数据，不从 file:// fetch 外部 wasm；复用现有主线程解析及导出模块。
- 棋盘内置 SVG、光标、图标字体和 CSS url 资源须随包嵌入，不仅内联 JS/CSS；复用主线程独立渲染器，检查贴图首次加载及发布包真实 URL 产物，不据单文件插件 README 就承诺 SVG 自动处理。
- 清除运行时外部 module import、懒加载 chunk、modulepreload 和资源加载 URL；仅设 `base: './'` 不满足目标。不引入 Service Worker/PWA 作为首次离线启动的前提。
- 本地入口直接初始化共享 CSS 及 i18n，不为文件选择新增独立主题/语言工具栏；中英文表达式帮助随包交付为静态 HTML，优先从当前 VitePress Markdown 生成，避免另维护一份说明。getDocsUrl 在离线构建指向包内帮助，不保留失效的 `/docs/` 路径。
- 检查 file:// 下配置存储、剪贴板、下载和 WebCodecs 的实际表现。已有 helper 能满足时直接复用，遇到缺口先完善公共 helper；不能因文件来源是本地就自动上传或请求后端。

### 自动工作流

- 新增独立离线构建工作流（拟 `.github/workflows/offline-analyzer.yml`），支持手动触发、相关路径的 PR 验证及 tag 构建；沿用项目 actions 版本与 Node 24，使用锁文件安装，不执行 npm update。
- 网站构建已通过 npm pre hook 先生成离线 ZIP，并作为 dist/assets 的静态文件随现有 tag 工作流发布；独立 upload-artifact 工作流仍待接入，不需要修改部署命令或依赖额外下载域名。
- 工作流执行离线构建、必要的类型/单元与产物检查，使用 upload-artifact 提供离线包下载，至少包含主 HTML、包内帮助及简短中英文使用说明。Actions 下载的 ZIP 解压后即可打开主 HTML，不制造多层 ZIP。
- PR 和 tag 流程不依赖生产部署密钥，不执行 SCP 或部署网站。现有 frontend.yml 的构建不会自动涵盖独立入口，现有 build.yml 是带生产上传的 tag 工作流，不直接复用其部署步骤。
- tag 附加 GitHub Release 文件不作为本阶段默认动作；先完成可下载的构建 artifact。工作流触发路径涵盖分析器、本地入口、共享 CSS/i18n、依赖锁文件、构建脚本和离线帮助源。

### 计数器验收（交互待用户验证）

- `d(expr)` 默认比较相邻采样点，`d(expr, n)` 按当前行筛选及同毫秒去重后（连续模式补齐空白毫秒）的采样点数量回溯 n 点；n 必须是正整数，支持步长表达式、复合表达式和不同步长嵌套。缺少前驱返回 `NaN`，差分先于时间插值及格式化，多个轨道引用读取同一结果。条件分支跳过某次调用、倒退或往返定位不改变前驱语义；文档链接、步长错误、前驱不足及预览保存由组件测试验证。
- 信息区独立于计数器，宽容器在计数器上方共享面板，窄容器位于工作区顶端；默认四行站内信息完整可读，支持自定义 `info` 插槽。计数器每行仅显示一个数值，纵向排满后转到右侧下一列，使用横向滚动条，不以纵向滚动代替排列。面板缩放后按可用高度重排但保留逻辑顺序，滚动不带动信息、不撑开页面布局。
- 数值计数器底部按顺序显示通用设置、导入配置、导出到剪贴板三个按钮，数据横向滚动时按钮行保持不动，数据排列高度扣除按钮行高度。通用设置可分别调整 key 列及数值列的列宽并持久化，默认分别为 80px、96px，不设置范围限制；导入通过 textarea 粘贴 JSON，失败保留输入及配置并显示错误；导出复制 JSON 配置而非实时数值或采样数据，不包含录像对象、进度或区间信息。导出后再次导入，保留每行 key、expression、format、samplingMode 和顺序，不重新生成 key。
- 网站信息提供四行展示并通过一次性接口读取，信息加载或失败不阻塞文件计数器、播放及编辑。缺少比赛时不显示比赛链接，无当前录像入榜项目时显示未入榜，请求失败显示错误；字段核对仍未实现，不宣称核对通过。
- 文件解析计数器使用 Analyzer 独立配置，默认三行 `Bvs`、`Ces`、`Mov`（连续采样的 1000 点差分速率），表达式仅能引用前述 13 个动态变量及 21 个静态变量，行名称即 key，保留字段原值并随统一进度更新；每次求值都检查结果为单一数字，允许并显示 `NaN` 和正负无穷，不把字符串、数组、布尔值或函数作为正常数值。解析、求值和类型错误直接在对应数值格子显示，不伪造默认值，不修改 VideoPlayer 的 localStorage。
- 每行左侧 handle 打开 tooltip 菜单，当前包含在上方添加、在下方添加、移动位置、编辑和发送到 plot；移动弹窗按正/负偏移向下/向上改变逻辑位置并支持跨列，越界分别截断到首行或末行，不循环。计数器行编辑弹窗只修改目标行的公式、数字格式及采样模式，不与轨道共享。取消不改配置，操作不跳转或重置播放。
- 添加弹窗填写 key、公式、数字格式及采样模式，默认格式 `.3f`、按键采样；key 必填且唯一，取消或重复 key 不添加并保留校验失败草稿。按逻辑行数组在当前行之前或之后插入，不以视觉列位置计算目标；覆盖首行、末行及跨列边界。插入后按纵向优先顺序重新排布并持久化，原行配置及已有 plot 轨道引用保持不变，不改变播放位置或播放/暂停状态。
- 各行通过普通文本 input 编辑 `d3-format` 格式字符串，独立设置数字显示，默认 `.3f`，移动及重新打开保留；只改变显示，不改变表达式原始结果和时间轴轨道数据，错误内容不经过数字格式化，`NaN` 和正负无穷仍能显示。
- 计数器及数据轨道共用连续、按键事件、局面变化三种采样模式及采样数据，移除原每个事件模式，默认仍为按键事件模式。先筛选符合模式的事件，再按每毫秒保留原数组中的最后一个符合条件事件。连续模式覆盖所有事件类型，无事件的毫秒向前 fallback，所有字段含 `time` 保持最近原生事件原值，每毫秒仍独立求值；按键模式不被同毫秒的后续鼠标移动覆盖，局面变化模式不被后续不改变局面的事件覆盖。采样点使用唯一毫秒时间戳，切换模式同步更新计数器及轨道且不影响播放状态；samplingMode 随行保存并完整导入导出。
- 相邻点仅按时间线性插值，不再按当前事件索引选择或插值。范围外保持最近端点原值，只有一个点时保持该值。`NaN` 和正负无穷不经过过滤或替换，插值的运算结果原样保留，数字格式仅在取值或插值后应用。本轮不增加无采样点或错误端点插值的验收场景。验证采样去重不改变原始事件、轨迹及关键帧数据。

### 时间轴及后续功能验收（时间轴交互待用户验证）

- 发送到 plot 使用下拉框选择目标，选项对应时间轴已有 plot 并显示当前名称；传递原计数器行 key，每次均在所选 plot 的轨道数组末尾追加条目，不创建新的独立单轨道布局单元，也不按 key、公式或轨道内容去重。验证同 plot 重复发送及跨 plot 重复添加均完整保留条目，不误加到其他 plot；移动原行或修改 plot 名称不改变数据关联，编辑公式后所有对应条目使用更新后的公式。
- 数据轨道引用原计数器数据，不复制计数器配置或另行采样求值；计数器侧修改公式、格式或采样模式后，所有引用该行的轨道读取更新后的结果。轨道不使用或打开计数器设置弹窗，不提供独立的公式或采样模式编辑副本。
- 网站信息验收：专用接口一次性返回主人 ID、全部比赛 ID、当前录像的各榜名次、文件名和 `VideoModel`、`ExpandVideoModel` 全部字段，名次直接查询 Redis。前端不拆分信息请求或随播放帧重复请求；切换录像清空旧信息并防止旧响应回写。缺少比赛、未入榜和请求失败分别处理，PlayerName、时间和文件名按当前录像展示。
- 字段核对恢复开发后验收：解析分析后按完整字段清单核对网站信息；一致数据不误报，中途播放值不会被当作最终结果。不一致时明显显示错误通知，列出录像 ID、差异字段和双方值，并建议联系管理员修复；请求或解析失败不冒充核对通过。具体精度及站内字段规则确认后补充对应测试。
- 自定义事件计算已有单元测试，页面待验收：仅允许 boolean/number/string 结果，使用原生布尔转换；验证 `NaN`、零和空字符串未发生，非空字符串及无穷值发生。与连续采样使用相同整数毫秒，每毫秒先保留最后一个原生事件再求值，无事件的毫秒向前 fallback（包括 `time`），每毫秒独立求值，脉冲可连续发生且引用相同来源事件索引；验证同毫秒前真后假不产生事件，前假后真仅产生一次脉冲，持续事件按保留的采样点分组。计数器行采样模式不影响自定义事件结果，原生数组、关键帧及原有轨迹数量不变。
- 验证自定义事件与计数器支持相同变量、工具函数、条件及差分（含采样点步长和嵌套），赋值仍禁用；最终结果类型按事件要求单独检查。解析或求值错误以及数组、对象、函数、null、undefined 等非法返回均判为未发生，不沿用前值、不跳过该采样、不阻止其他事件计算；持续段遇到错误采样时正常结束，后续恢复正常结果时可形成新事件段。差分前驱不足的 `NaN` 判为未发生，计数器仍按原规则显示数值或错误。
- 验证持续段代码结束边界为首次未发生的采样，渲染终点为最后一次发生的采样，未发生采样不进入线段或持续轨迹；录像末尾仍发生时持续并绘制到录像结束。不为零长度持续段添加独立处理，每种事件独占时间轴一行，不引入跨行重叠避让。
- 自定义事件行位于顶部时间轴与 plot 之间，每种事件固定高度一行，开头显示 key、末尾设置按钮，持续事件使用线段、脉冲事件使用 marker。验证类型、颜色及对应样式设置，刷新恢复配置、换录像重算事件结果，时间窗变化后与数据 plot 保持对齐；不加入 plot 或参与数据纵轴。
- 棋盘事件图层验收：多选已有自定义事件，脉冲 marker 对齐保留的原生事件鼠标位置，持续事件轨迹使用对应 line style 并有方向箭头；颜色和样式在时间轴修改后同步到棋盘。验证原生 SVG 在三种大小模式和布局调整后坐标一致，多选、时间范围和箭头设置可恢复；改名同步选择，删除清理选择，当前及之前模式不显示未来事件；视频导出完全不包含本图层，开关或选择不改变现有导出的画面。
- 时间轴区域顶部显示时间轴，其下为自定义事件行，再下方纵向排列数据 plot，首次使用默认 `left`、`right` 两个持续性事件和两个 plot，轨道分别为 `[Bvs, Ces]` 和 `[Mov]`，名称为 `Plot 1`、`Plot 2`，支持新增空 plot；新添加的 plot 为空，有已保存配置时恢复用户配置。每个 plot 本身为数据轨道数组，空 plot 为 `[]`，保留顺序及重复条目。plot 只支持数据轨道，所有绘图区与顶部时间轴横向对齐。
- 同 plot 数据轨道共用 y 轴，以所有数据轨道整份录像的采样数据自动计算范围及刻度；增加轨道、修改公式或采样后共同更新，不随播放、平移或缩放改变取数范围。不同 plot 使用各自的纵轴，自定义事件行不参与数据纵轴的范围计算。非有限值沿用绘图库行为，不改变原始数据。
- plot 右侧控件纵向排列，添加轨道通过下拉框选择，每次向该 plot 追加条目，即使相同轨道已存在也不禁用或省略添加。删除 plot 必须弹窗二次确认，取消保留全部内容，确认只删除 plot 及其轨道关联，不删除计数器原行；添加的新 plot 不自动加入轨道。
- 左侧纵向 plot 名称可修改，并作为拖动排序 handle；上下边界调整整个 plot 高度，只改变目标 plot 高度，相邻 plot 高度不变，位置随正常文档流变化。操作互不误触，不修改播放状态，plot 名称、轨道关联、顺序及高度按已有设置持久化原则保存。
- plot 名称右侧显示窄矩形图例，按轨道数组条目数量沿纵向均匀分割，各块填充 plot 自动分配的对应轨道颜色、文本显示对应 key，重复 key 的条目各自显示图例块，不合并。颜色与实际绘制一致，名称使用计数器 key；空 plot 不显示伪造的图例项。修改 plot 名称不改变轨道 key 或原公式关联，名称及图例区域不挤入共享时间绘图区。
- 每个 plot 使用固定 Tableau 10 色板，新条目选使用次数最少的颜色、同次数按色板顺序；前十条颜色不同，超过十条可复用。增删或排序、改名、公式/采样变更、录像切换及刷新不改变已有条目的颜色；删除后颜色可复用，失效 key 保留颜色占用，重复 key 的条目分别配色，颜色随条目持久化。验证删除中间条目后剩余曲线、legend 及悬停颜色不发生变化。
- 点击某个 legend 打开包含移除操作的 tooltip，只移除对应 plot 内的该数组条目；重复 key 的其他条目、其他 plot 和计数器原行保持不变。key 失效后条目和 legend 保留原位置，不绘制曲线或参与纵轴和悬停计算，仍可手动删除；配置导入造成的失效 key 也不自动清理。
- 初始显示完整录像，此时禁止平移；仅顶部刻度栏支持滚轮缩放，共用同一横向时间窗，每个 plot 的纵轴保持整份录像的数值范围。plot 绘图区、标题、图例、右侧控件和区域外普通滚动，以及 Ctrl/Cmd 加滚轮的浏览器行为不受影响。缩放后拖动顶部刻度栏平移，整个时间窗限制在 `[0, durationMs]` 内，边界截断时保持窗口长度，不显示范围外空白、不修改播放时间；选定区间和采样范围不限制平移。点击或拖动 plot 绘图区修改 `currentMs` 并保留播放状态。
- 悬停竖线在所有 plot 使用相同时间坐标，每个 plot 内各条数据轨道分别显示交点数值，以 key 和颜色区分，使用已有采样及行 format；悬停不改变录像定位或播放时间。单条数据轨道的采样时间戳唯一，无需显示同轨道同时间戳的多个事件值；多条轨道各自的交点仍全部显示。
- 时间轴与进度条共用区间端点，端点修改即时同步，布局切换不创建独立区间或重置选定范围；计数器、时间轴及分析数据均使用页面的共享时间和录像状态，不各自定位解析对象。
- 按键 marker 在同一个 MouseTrace 中按原事件顺序绘制，不去重、不另建 DOM 层；四类开关保留样式，验证全部形状/大小/颜色/描边/不透明度及实际格子大小对齐。页面和导出使用同一套 props，布局切换和重开保留设置。
- 已实现关键帧验收：严格相邻事件索引、先设置时间后设置索引、显示前置局面；同时间戳分别访问，计数器仍按时间插值，不要求动态 getter 与前置局面一致。保留播放/暂停状态，普通进度跳转及播放推进恢复正常定位；无相邻事件时错误通知，不改变索引、时间或播放状态。上游修复后再核对完整同步。
- 视频导出实施后验证完整录像及选定时间区间的实际可播放文件，不以播放时钟测试代替文件验证。零长度区间不能区间导出，不影响全部导出；时间区间只输出一次，倍率与导出前进度条一致。
- 验证空间区域默认全盘，四边下标均包含端点、越界及反序不能提交，单格/单行/单列可导出；输出尺寸沿用当前实际格子大小，只包含棋盘，参与导出的图层及透明度、主题、光标、轨迹效果与同时间界面一致，棋盘事件 SVG 图层明确排除。区域外画面正确裁切，区间首帧保留应显示的历史拖尾。
- 验证导出期间全页面控件被冻结，只有进度及取消可用；页面进度、棋盘、计数器和时间轴不随导出帧推进。独立解析副本不重新请求，完成、取消和失败均释放副本和渲染资源并恢复播放状态，取消不下载不完整文件，失败有明确通知。各个可选格式/编码器、帧率及质量选项分别验证，浏览器缺失能力时不得伪装成功。
